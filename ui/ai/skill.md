# Building with @kerfjs/ui

Read `../docs/component-selection.md` first, then the component reference index
`./components/README.md` and the `./components/<id>.md` page of every component
you use (selection, imports, props link, composition, state and wiring,
accessibility, styling boundary, diagnostics), then
`./public-api-signatures-v1.md`, `./compile-time-contracts-v1.json`,
`./webawesome-jsx-signatures-v1.md`,
`../docs/recipes.md`, `../README.md`,
`../docs/component-contract.md`, and `../docs/accessibility.md` before changing
a consuming interface. Use the signature snapshot for exact props, callbacks,
return values, and supported import paths; do not infer them from examples.
Treat each `KUI-T###` contract as an exact declaration guarantee, including its
documented dynamic-data widening. Do not extend those diagnostics to child
markup, live DOM relationships, disposer invocation, or other conditions that
TypeScript cannot prove from one call.

Before writing JSX, run the
[component-selection decision pass](../docs/component-selection.md#decision-pass-before-jsx-or-css):
name the user's task and interaction, find the matching Kerf or application
component, and use its public props. Compose existing primitives for layout; an
app component is for a repeatable domain contract or new structure, not a copy
of a Kerf component with local CSS. For each proposed `div`, `span`, fragment,
class, or rule, identify the semantics, interaction, accessibility, or
app-owned geometry it supplies; remove it when a selected component already
supplies that job. Plan one owner for the surface, inset, scrollport, and gaps.
Use the shared spacing scale by relationship and preserve useful empty space.
Compare the result with adjacent screens and inspect real wide/narrow browser
states before treating a passing analyzer or test as a design approval.

### Shared semantic tones

`SemanticTone` is the shared color-role type for `Badge`, `Chip`, `StateBanner`,
and semantic `ContentItem` appearances: `neutral`, `info`, `pop`, `success`,
`warning`, and `danger`. Import it as a type from `@kerfjs/ui`,
`@kerfjs/ui/badge`, `@kerfjs/ui/state-banner`, or `@kerfjs/ui/content-item`.
Use `info` for the role backed by the existing `--kui-color-brand-*` tokens.
Migrate Badge/Chip `tone="brand"` to `tone="info"`; `BadgeTone` and
`StateBannerTone` remain deprecated aliases of `SemanticTone`.

### Lowered surfaces are translucent

The sunken/lowered background is a semi-transparent color, not a solid canvas.
`--wa-color-surface-lowered` and its Kerf mirror
`--kui-color-surface-lowered` provide the shared tint;
`--kui-color-neutral-fill-quiet` uses that tint too. `SunkenPanel`, sunken
`Pane`/`Workbench`/`TabNavigator` surfaces, and Web Awesome
`appearance="sunken"` consume it through `--kui-sunken-panel-background` or
`--kui-wa-sunken-background` (their optional override tokens). Each painted
layer composites with everything beneath it. Use a separate lowered component
when its nested depth is intentional; do not paint the same visual surface
twice through a wrapper, a second background, or an unnecessary override.
Check the resulting contrast in both color schemes, especially over a custom
backdrop. See `../docs/webawesome-theme.md#contextual-transparency`.

### Clear chrome over imagery

For a header or bar laid over imagery (an Apple-Music-style detail page), use
the `clear` presentation (`Pane headerPresentation`, `NavStack
chromePresentation` / `bottomToolbarPresentation`, `TabNavigator
barPresentation`) instead of making `overlay` chrome transparent with CSS.
Put its controls in `ToolbarControlGroup material="glass"` groups, and add
`scrollEdge="material"` (or `"surface"`, with `scrollEdgeDistance`, default
60px) to fade a backing in gradually as content scrolls beneath the bar (it
stays clear otherwise); give the opening `BackdropImage` `underChrome` so its artwork runs beneath the clear header. A clear bar draws no divider and turns opaque under reduced
transparency, increased contrast, and forced colors on its own.

### Core dialogs as bottom sheets

For a `kerfjs/overlay` `confirm` / `prompt` / `form` / `choice` (or `overlay()`)
with `presentation: 'bottom-sheet'`, import `@kerfjs/ui/overlay-sheet.css` once
instead of writing sheet CSS, pass `exitClass: 'kui-overlay-sheet-exit'` with an
`exitDuration` for the slide out, and compose the content through the dialog's
`render` slot (on kerfjs 4.x, with native buttons for the wired controls). For a sheet the person
can resize, add the `kui-overlay-sheet-resizable` class
(`className: 'kerf-overlay kui-overlay-sheet-resizable'`) and call
`wireOverlaySheets()` from `@kerfjs/ui/wire-overlay-sheets` once per container,
instead of building a grabber.

### App-chosen surface colors

For a surface in its own color (a media page in its artwork's color), set the
typed `background` prop instead of CSS: `Pane` (also `PaneConfig`, so Workbench
panels, CollapsiblePanel, and NavStack view panes forward it), `NavStack`,
`TabNavigator`, and each `TabNavigatorTab`. Pass a `@kerfjs/ui/css-values`
color (`uiColor(...)`, `fillColor(...)`, `colorVar(...)`); it replaces the
default or sunken fill, overlay chrome keeps its material, and forced colors
paint `Canvas`. Never select `.kui-pane` or a layout class to recolor it. You
own the contrast of the content over the color.

For a region that takes on a color, such as a media page in its artwork's
color, set `tint={{ color, scheme }}` on the same components (and
`TabNavigatorTab`, `PaneConfig`) instead: you declare whether the color is a
`'light'` or `'dark'` surface, and the scope re-derives surface, text, quiet
text, link, fills, and chrome material from it with lightness clamped to keep
text at WCAG AA. Add `accent` to re-derive the brand ramp (loud fills, links, focus ring) from the artwork's vivid color with the same AA clamps. Never restyle tokens by hand inside a tinted region.

## Components own their styles; configure, never override

This is the rule every Kerf UI surface follows, and applications and
component packages built on Kerf UI must follow it too:

`Catalog` owns its preview stage in every package: its shipped styles fill the
Pane scroller for short specimens and grow for tall ones. Import its browser
styles or companion CSS; never add a demo-specific stage height, backdrop, or
Pane override to imitate the Kerf UI UX demo.

- **A component styles only itself.** Change how a component looks or sits
  through its typed props and data attributes (size, density, inset,
  presentation, tone, `dividerSides`, `ToolbarConfig`, `PaneConfig`, …). Never
  restyle a component from outside it: no application or parent CSS that
  selects a `.kui-*` class, a `[data-component]` root, a `wa-*` element a Kerf
  component renders, or its `::part()`s, and no hook class added to a
  component's root so that it can be restyled.
- **Owned implementation details are available.** A component may render raw
  HTML or Web Awesome elements and style those elements when it creates them,
  controls their state, and keeps the selectors in its own stylesheet. That
  permission stops at every nested Kerf or application component boundary;
  ownership follows the child component, even when the parent rendered it.
- **Configuration, not overrides.** Do not write another component's private
  `--_kui-*` variables or reach for its `--kui-*` tokens to change layout,
  size, padding, or framing when a prop exists. Theme tokens are for theming
  (the semantic color ramps, the spacing scale); layout and geometry come from
  props.
- **Compose, then let the child adapt.** When a component needs to look
  different inside another one, the child styles itself in that context, in
  its own stylesheet (`.kui-toolbar-control-group[data-size="compact"] >
.kui-popup-menu { … }` lives with PopupMenu). A parent may key its
  own styles on a child's state (`:has(> .kui-select[open])`) and name the
  child by class, never by bare `wa-*` tag. Values a parent provides to its
  children are custom properties named after the parent.
- **Missing configuration is a component gap.** When no prop gives you what
  you need, report it (open an upstream feature request) instead of
  overriding. Your own components follow the same rule: expose configuration,
  and let each component own its styles.
- **Thin compositions usually need no CSS.** A component that only chooses and
  connects other components should configure their props and slots without a
  stylesheet. Add CSS only for raw elements or layout that the composition
  itself owns; never use a composition stylesheet to normalize or override its
  children.

`kerf-ui-analyze` and `kerf-ui-doctor` enforce this downstream: `KUI-L019`
(a rule whose subject is a cataloged component), `KUI-L020` (another
component's private `--_*` variable), `KUI-L021` (a token a typed prop sets),
and `KUI-L022` (a hook class on a component's root) are errors, and
the analyzer resolves cataloged application imports through TypeScript `paths`
aliases as well as direct relative imports.
`eslint-plugin-kerfjs`'s `ui-component-ownership` reports `KUI-L020` /
`KUI-L021` in script. Repair them with the configuration each message names;
when none exists, report the component gap rather than suppressing the finding.
For compact known activity, give `LoadingSpinner` its `size` prop (`xs` through
`xl`, or a positive pixel number) instead of styling its SVG; omitted size is
1em.
For an application's own components, configure Doctor with
`"ownership": "component"`, `"implicitComponentOwnership": true`, and
`"ownershipContext": "any-package"`; declare each catalog entry's
`styleSources` so sibling components cannot style one another. Package
ownership remains the compatibility default and does not establish those
application-level boundaries.

Read `../docs/webawesome-theme.md` when using Web Awesome components or changing
shared theme tokens. When overriding a loud fill
(`--wa-color-{tone}-fill-loud`), set the matching `--wa-color-{tone}-on-loud`
in the same selector and at-rule scope with a foreground that clears 4.5:1;
the analyzer reports an override with no governing `on-loud` (same or ancestor
scope, in any stylesheet the entry loads), or a literal pair below 4.5:1, as
review finding `KUI-L018`.

Before choosing or aligning components, look for a consumer-owned catalog that
conforms to `./component-catalog-extension.schema.json`. Treat its entries as a
second, package-qualified input beside `./component-catalog.json`: search both,
preserve their source identity, and use the shared `geometry` vocabulary across
their composition boundary. An extension entry's optional `uses` ids resolve
against both catalogs; its `source` and `demoSource` are repository-relative
files for consumer catalog links. A project with `kerf.components.json` generates
that extension with `kerf-component-catalog` (`kerfComponentCatalog.selectionOutput`
plus per-component `selection` blocks) rather than hand-writing it. When a consuming project has reusable visual
components, derive demo rows with `@kerfjs/ui/catalog-projection` or
`kerf-catalog-demo --write`, then guard drift with `--check`; see
`../docs/catalog.md`. For a local catalog's UX Review **Capture region** link,
add `uxReviewPlugin()` from the Node-only `@kerfjs/ui/vite-ux-review` to the
Vite config (a catalog served by the app's own backend mounts that subpath's
`uxReviewProjectResponse` or `uxReviewMiddleware` on its development server
only), report the project with `wireCatalog`'s `onUxReviewProject`, and
render `Catalog` with `uxReview={{ projectDirectory }}`; never hand-roll the
endpoint or the `uxreview://` link. For per-entry variant/state controls, pass
them as `Catalog`'s `settings` (with `settingsCollapsed` and the same signal as
`wireCatalog`'s `settingsCollapsed`); never build a separate settings aside and
toggle. Prefer its generated `component-composition.json`. A package
scaffolded by `create-kerf-component` owns the decisions in
`kerf.components.json`; run `npm run catalog:check` before using its output. If
no generated extension exists, start from the checked examples and require the
author to supply missing semantic and geometry decisions; never infer them from
rendered appearance. A `data-*` attribute listed in an entry's
`wiring.stateAttributes` belongs to the named helper: never render, remove, or
branch on it as application state. A package entry's public classes follow the same rule
as Kerf UI's: write only its `boundaries.placeableClasses` onto your own
elements (never on a plain `boundaries.rootElement` tag), and render the
package's component for every other class (`KUI-L103`).

The component pages are generated from `component-catalog.json` and its
composition layer, `component-composition.json`; do not load those large JSON
files to choose or compose components. They are the tool-facing sources: when a
tool must mechanically evaluate selection, delivery, compatibility, or
composition, use `component-catalog.json` for selection, delivery, and
compatibility and `component-composition.json` for composition. Join catalogs by `key` (`package:id`), never bare `id`. Treat
`generated-permissive-default` composition provenance as unknown/allowed, not
as a prohibition. Emit a diagnostic only after mechanically establishing its
exact `when` condition; subjective guidance stays prose. App entries use the
composition extension schema and retain their own package identity across Kerf edges.
Treat a zone's optional `jsx.prop` as its only authoritative JSX binding; never
assume the zone id itself is a prop. `children` carries one homogeneous primary
region. Semantic positions and replacement content use explicit named content
props (`header`, `footer`, `leading`, `trailing`, `action`, and similar). Multi-
content positions use the recursive `KerfUiContent` type: `SafeHtml`, runtime-
empty boolean/nullish values, and readonly nested arrays. Put conditional
components and mapped component arrays directly in these positions; do not add
a `Fragment` merely to satisfy types. Arbitrary strings, numbers, and signals
are rejected unless a component explicitly exposes a text position such as
`ListInsetText`. These are typed props, not native `<slot>` elements,
wrapper slot components, or a generic `slots` object. Preserve dynamic
expressions as unknown when their content cannot be established statically.
Stable single-root Kerf UI components separately accept native `slot="name"`
for direct light-DOM composition inside a custom element and preserve it across
rerenders. This is the one explicit native interop attribute, not permission to
spread arbitrary native attributes. `ResizableRegion` and `CollapsiblePanel`
remain excluded because their optional restore control makes them multi-root;
use a slotted single-root child or `CollapsiblePanelToggle` instead.

Before selecting for an application, call the Node-side discovery API in
`./application-ui-profile.mjs` (or implement its documented filename/order)
from the workspace root and target directory. Apply package defaults first,
then workspace policy, then directory-local profiles parent-to-child. Honor the
resolved profile's preferences, theme/density allowlists, tokens, layout, and
responsive policy. Treat only its exact, narrow exception targets as waived;
never generalize an exception to siblings or infer product data into a profile.
Surface every returned source file + JSON-path diagnostic before generating UI.
Each layer is checked against its then-effective catalogs; later overrides do
not excuse broken catalogs or stale references in a parent layer. Synchronous
ESLint integrations use `./application-ui-profile-sync.cjs` and surface any
failure as `KUI-L090`.

Choose from the need, not from visual resemblance:

1. Search the consumer extension first, then the Kerf catalog. Prefer a Kerf UI component, then a native HTML element, using each naturally for what it is good at. Web Awesome is an optional integration: use its remaining supported elements only in an application that has adopted it, never one a Kerf component replaces.
2. Reuse a primitive when purpose, anatomy, state, and interaction match.
3. Compose primitives for recurring layout through public props and tokens. Never select one component from another component's stylesheet.
4. Add a thin application adapter for copy, domain mapping, actions, routing, persistence, permissions, and transport.
5. Build custom markup only when the semantic contract differs; if it recurs across products, open an upstream component or recipe request.

### Application interaction choices

For ordinary server-backed freshness, prefer event-driven updates,
subscriptions, or explicit user refresh when they meet the product need. Use
fixed-interval polling when periodic sampling is genuinely required or no
suitable update channel exists; choose the interval deliberately and cancel
the timer when its owning view is disposed.

Match cursor cues to enabled behavior: pointer for actionable targets,
grab/grabbing or resize cues for real drag and resize affordances, and default
or disabled cues for unavailable actions. Align semantic controls, keyboard
behavior, focus treatment, and disabled state with those cues; a cursor alone
cannot explain an interaction. See [accessibility contracts](../docs/accessibility.md)
and [interaction principles](../docs/apple-hig.md#interaction).

### Interface copy capitalization

Follow Apple's split; it is the package default, so never mix styles from
screen to screen. **Names are title style; descriptions are sentence style.**
Title style covers button and menu-item labels, popup-menu triggers and group
headings, segments, `Select` choices, tabs, page/view/pane/dialog/toolbar
titles, back labels, `ListHeader` and column headings, field labels, the
accessible name of an icon-only control, and fragment `EmptyState`/`StateBanner`
titles ("Save Draft", "Back to Inbox", "Needs Attention", "Release Date").
Sentence style covers body copy, descriptions and details, dialog/alert
messages, tooltips, placeholders, checkbox/switch/radio option text, and
status lines or counts ("Saved just now"). A title written as a complete
sentence takes sentence style and ending punctuation. In title style,
capitalize the first and last word and every noun, pronoun, verb, adjective,
adverb, subordinating conjunction, and phrasal-verb particle ("Log In");
lowercase articles, coordinating conjunctions, `to` in infinitives, `as`, and
prepositions of four letters or fewer unless first or last. Keep brand
spellings (iOS, macOS) and never recapitalize user data. `kerf-ui-doctor`
reports lowercase words in known title-style labels as `KUI-D040`. See
[Writing interface copy](../docs/writing.md#capitalization).

Hard rules:

1. Import visual components from explicit JavaScript subpaths. In CSS-aware browser builds each subpath brings in its own reachable CSS, including UI subcomponents, while unrelated CSS remains out. The root barrel and `@kerfjs/ui/unstyled` are CSS-free; pair the root barrel with `styles.css` only when the complete layer is intentional. Manual CSS subpaths remain available for custom pipelines. When a public subpath exposes several visual components, implement it as a folder with one component per file and one owned stylesheet per visual component; compatibility entrypoints only re-export the component modules or import their owner stylesheets.
2. Components return Kerf `SafeHtml`. Never pass DOM nodes as children or use inline JSX event handlers.
3. Keep state, product copy, persistence, and domain mappings in the application. Do not add product-specific actions or fields to a generic component. Put ListItem/ListActionRow/ListHeader/TabBarItem domain `data-*` metadata in `rootAttributes`; use ListActionRow `trailingActionAttributes` and ListHeader `triggerAttributes` only for domain `data-*` or native popover target/action and `aria-controls`/`aria-haspopup`. These slots do not replace component-owned action, item/tab identity, selection, disclosure, naming, disabled, icon, or role semantics.
4. Wire `data-action` hooks from one stable root with `delegate()` or `delegateActions()` and retain disposers.
5. Configure components through their typed props; components own their own styles (see "Components own their styles; configure, never override" above). Use the opinionated `--kui-color-*` semantic ramps for theming, not to reshape a component. Use `pop` only for attractive non-status emphasis such as featured, novel, or celebratory content; never substitute it for info, success, warning, or danger. Set a theme token only at the narrowest useful scope, and never where an equivalent prop exists. `publicClasses` exist for diagnostics, tooling, tests, and package-owned composition, not application styling. Never target a Kerf or Web Awesome component from application CSS; add missing configuration to the owner.
6. `Select` is pure until the app explicitly imports `@kerfjs/ui/select/register`; once registered, an icon-only `Select` (and, via `@kerfjs/ui/popup-menu/register`, an icon-only `PopupMenu`) shows an `aria-hidden` help tag repeating its accessible name (and a Select's current choice) on hover and keyboard focus, hidden while its popup is open — never add a `title` or your own tooltip to these triggers. The same installer tags an icon-only `<button>` or link in a `ToolbarControlGroup` named by `aria-label` (no visible text, no `title`); a toolbar with such buttons but no registered Select or PopupMenu imports `@kerfjs/ui/help-tags/register` once. Name those buttons with `aria-label`, not `title`: a `title` keeps the browser tooltip and skips the tag. Do not import Web Awesome's full registration bundle. When an app writes direct `wa-*` JSX, add `import type {} from '@kerfjs/ui/webawesome'` for the catalog-supported intrinsic-element declarations, import the CSS-only `@kerfjs/ui/webawesome.css` theme once, and keep importing individual Web Awesome component modules so their JavaScript remains tree-shakeable. The type boundary emits no code and registers nothing. Pass icon-bearing `choices` and `renderSelected` content normally: `Select` preserves its option icons across Kerf rerenders and keys selected content by the controlled value, so app wrappers must not add competing morph-control attributes. Give it a visible `label` or an `ariaLabel` for a visually hidden name; the nonempty visible label takes precedence and the package names its native trigger, including with `renderSelected`, without adding label geometry. Use `hint` for persistent supporting text below the control and `placeholderText` only for the empty value inside the closed control; loading placeholders retain the hint. For any number of choices set `multiple` with an array `value`: the popup stays open while choices toggle and closes on an outside press or Escape, the closed control summarizes the chosen labels, and `change` reports the value array; do not add app code to keep it open or to render tags. For a toolbar filter menu, add `selectedPresentation="icon-only"` plus a fixed `triggerIcon` (such as a funnel `LucideIcon`): the trigger shows that icon, a count badge while any choice is chosen, and ends its accessible name with the chosen labels ("Filter by label: Bug, Docs"); do not render your own count badge or rewrite the name. When testing name or description, target the element with the `combobox` role (the native trigger) rather than the `kui-select` root; the hint is already its `aria-description`, so do not add another.
7. Decorative icons are hidden; controls are named; focus is visible; state never relies on color alone; reduced motion and increased contrast remain usable. When the app detects a low-power device, it sets `data-kui-effects="static"` on the root element to turn backdrop materials opaque and stop scroll-driven animations; `@media (update: slow)` does the same automatically. `DisclosureArrow` defaults to an 18px root-scaled visual; size it with its typed `size` prop (`size={remify(24)}`); it never becomes the interaction or accessible-name owner. Put it in an owning native control with a stable accessible name and controlled `aria-expanded`. `ListHeader` toggle mode supplies it when `actionIcon` is omitted, but the app must reveal matching content; a custom icon replaces it. Author replacement icon content facing right before its configured direction transform is applied. Direction changes take the shortest rotation path, with counterclockwise chosen for a 180-degree closed-to-open tie. Kerf `Select` separately keeps its intrinsic Web Awesome expand glyph at `--kui-disclosure-icon-scale: .5`; an icon-only toolbar Select may set `caret={false}` for a round trigger while preserving its help tag and keyboard listbox, and a custom `renderSelected` icon stays centered.

Set `responsiveFillAt="narrow"` or `"compact"` when a responsive composition exposes the pane as its only inline track; the component fills that track and hides its dormant separator. For compact overlays, set `presentation="overlay"` and the overlay maximum variables. A lone child (normally a `Pane`) fills the region and owns scrolling; several children stack at natural height. For a tab-local action followed by a separately pinned workspace action, set `trailingPlacement="adjacent"`, put the local action in `trailing`, and the workspace action in `end`; each action zone accepts one `ToolbarControlGroup` or a standalone `wa-button` when the action needs its own Web Awesome chrome. Use runtime-filtered `rootAttributes` for domain metadata and keep an optional `closeIcon` decorative and noninteractive.
11. Use token-controlled `SearchField` when free text and removable structured filters share one editor. Editable text stays DOM-owned between token changes; to replace the text programmatically (reseeding a persistent dialog's field on reopen, applying a saved search) change the field's `revision` along with `query` for an unmanaged field, or call `model.replace({ query, tokens })` for a model-managed field; never re-key a wrapper. The leading icon, first text line, clear action, and trailing slot share one fixed row when content wraps. The field subscribes only to `model.structure` (committed tokens, empty or non-empty text, editor revision), so plain typing never re-runs the host render; in the host's own render read `model.state.peek()` and bind `model.result` (or a `computed`) as a signal hole — reading `model.state.value` there re-renders the host on every keystroke. Otherwise the app owns parsing and suggestions; call `readSearchField()` on input, empty `textContent` on clear, use `placeSearchFieldCaret()` after explicit controlled focus changes, and call `wireSearchFields()` once so Enter submits without inserting a line break and keyboard chip deletion restores focus plus the text-relative caret after controlled replacement. `clearIcon` replaces the clear action's glyph (its `clearLabel` still names it). For a compact icon button beside the clear button (a search-syntax help glyph), pass `trailingAction: { icon, label, action, expanded?, pressed?, controls?, haspopup?, attributes? }` — it matches the clear button's size, hover, focus, and cursor in every presentation; set `expanded` for a disclosure or `pressed` for a toggle, never both, and never hand-style a button into `trailing`. Enable `collapsible` for an animated iconic closed state, standalone or inside `ToolbarControlGroup`; the field keeps text or tokens expanded, and `wireSearchFields()` manages the transient expand/collapse/focus by default (activate to reveal + focus, Escape or empty blur to collapse). Bind the field's `expanded` to the returned handle's `expanded(id)` signal or adopt your own via `collapsible.signals`; opt a behavior out only when the app must own it. Do not hand-roll the open handler, the focusout collapse, a clear-button mousedown guard, or reopening after controlled clear or Select All deletion — the helper keeps the replacement editor open and focused. Clear and deletion restoration finish at the replacement mutation checkpoint before the next input task, so shortcut-letter typing cannot escape to the page and delayed animation frames cannot overwrite a later selection. Persist both query and tokens returned by the DOM read. For real-app adoption it also provides a focusout keep-open exception (`data-search-field-keep-open` regions or `collapsible.keepOpenOn(target)`, so a sibling suggestions/date/help surface does not collapse an empty field), opt-in atomic-chip keyboard (`keyboard`: Backspace/Delete remove the adjacent chip via `onRemoveToken`, ArrowRight moves the caret past a trailing chip), and an `onEdit({id, editor, event})` input callback (the `InputEvent` lets you gate on `inputType`/`data`) — reach for these instead of re-adding hand-rolled keydown/input handlers around the field.
    An application helper can call `model.commit(value)` for the active `name:` prefix when it computes a valid value outside suggestions; invalid values and missing prefixes leave the query unchanged.

Show `Composition` as an entry tag instead of repeating the word in its name. Project each component's deterministic repository-relative demo source and existing documentation path so the detail can expose `View demo source` and `Read guidance` links without a runtime export; also derive first-party component implementation paths from their canonical browser imports, and label Web Awesome documentation as Kerf integration guidance. Put it in `ListInsetControl sides="trl"` beside a `ContentItem` value; give it an id and use `aria-labelledby` on the preview group. The app owns preview/edit state and hint copy.

`ToolbarControlGroup.tileTone` selects `neutral`, `brand`, `success`, `warning`, or `danger` quiet fill, matching quiet border, and on-quiet foreground for a non-interactive icon tile. Compose a contained `single` group whose only child is a direct decorative LucideIcon (`aria-hidden="true"`). Omission preserves the normal group palette. The prop does not recolor interactive, mixed, multi-control, or borderless groups; keep real actions in controls with their existing focus/hover/pressed treatments.

`ToolbarControlGroup` `material="glass"` paints a group that floats over imagery or a clear (transparent) toolbar on the translucent chrome material (`--kui-chrome-material` with the blur/saturate `--kui-chrome-material-filter`), with a specular edge in place of the gray border and a soft shadow. Its controls take `--kui-color-text`, so they stay at AA over any content; a raised or outline selection paints an opaque surface pill. The fill turns opaque under reduced transparency, increased contrast, static effects (`update: slow` or `:root[data-kui-effects="static"]`), or without backdrop-filter support, and paints Canvas/CanvasText in forced colors. A `tone="dark"` glass group keeps its loud fill and gains the blur and edge; a borderless group has no surface and ignores the material. Keep the solid default on an opaque toolbar, and never add your own `backdrop-filter` or translucent background to a group.

`ListItem`, `ListItemLink`, and `ListActionRow` take `iconTile` to present their leading `icon` in a filled 32px rounded tile holding an 18px glyph, for settings or command rows that identify each entry by color. Pass a tone (`neutral`, `brand`, `success`, `warning`, or `danger`) for the same quiet fill, matching quiet border, and on-quiet foreground as `ToolbarControlGroup.tileTone`, or `{ color, foreground? }` for an application color: `color` is a `CssColor` (`uiColor()`, `colorVar()`, or `fillColor('#e5484d')`) and `foreground` a `CssForegroundColor`; without one, the glyph is black or white, whichever contrasts with the fill. The tile sits 6px clear of a standard 44px row (a compact row is at least 42px tall), moves the label to the tile's edge, and keeps its colors when the row is hovered or selected. Never wrap the icon in your own tile or resize the row's icon slot.

For prominent content text, use `Text size="large"`; use `size="xlarge"` for display copy. Both sizes work with semantic `variant`, `tone`, and `font`, so keep heading levels based on the document outline.

For an exclusive choice among several visible options that must wrap (a labeled color palette), use `ChoiceChips` from `@kerfjs/ui/choice-chips`: separate pills backed by native radios, so the group is one Tab stop, arrow keys select, and the checked radio submits under `name`. Name it with `label` or `labelledBy` (a visible `FieldLabel`), lead choices with `swatch` (a `CssColor` such as `fillColor('#3b82f6')`, or `'transparent'` for the struck-through no-color dot) or `icon`, and handle the delegated `action` on `change`. Never wrap a `SegmentedControl` or button-appearance `wa-radio` set instead. When any number of the options may be on, give `value` a `readonly Value[]` and pick a model. `multiple: 'toggle'` (label filters, annotation intents) makes the pills native checkboxes in a `role="group"`: each its own Tab stop, a click or Space toggles it alone, and every checked value submits under `name` (read the checked boxes by name in the change handler). `multiple: true` is the desktop multi-select: an `aria-multiselectable` listbox where a click selects one chip, Cmd (Apple) or Ctrl (elsewhere) toggles one, and Shift extends a range; it is one Tab stop with arrow, Shift+arrow, Space, and Cmd/Ctrl+A selection, and hidden inputs submit under `name`. It requires `wireChoiceChips(root)` from `@kerfjs/ui/wire-choice-chips`, which fires `change` on the group (the group carries the `action`); read the set with `readChoiceChips(group)`. A multiple group takes no `required`. On dark inverse chrome, put the chips in a dark appearance scope (`.wa-dark` or any `color-scheme: dark` ancestor) instead of restyling them.

For removable tags use `Chip`, with `removeAction` for delegated handling and a specific `removeLabel` for the native button. `itemId` identifies the tag; the app owns removal. `size="compact"` and `disabled` replace app styling of raw `wa-tag` internals. Use `Badge` for non-interactive metadata. For a downloadable file or a short link, give `Chip` an `href` (optional `download`, `true` or a file name, and `external`) instead of styling an `<a>`: it renders a native link with chip geometry, icon, truncation, focus ring, and hover feedback, and cannot also carry a remove button. Inside a `brand-loud` or `neutral` ContentItem bubble set `tone="inherit"`, which follows the bubble's foreground with a currentColor border and no fill. For a short value the user activates once (a filter token in a search help popover that inserts itself into the query), give `Chip` an `action` and `itemId`: the whole chip becomes a native `<button type="button" data-action data-item-id>` with hover, press, focus-ring, and disabled states, and an optional `actionLabel` that contains the visible label. It cannot also take `href` or `removeAction`. A compact rounded action chip keeps a compact `Badge`'s height in a compact `ValueTable` cell, so use it there instead of a `Badge` the app makes clickable.

For a chat message or assistant prompt, use `MessageComposer` from `@kerfjs/ui/message-composer`: a raised frame whose border turns brand while focus is within, a borderless textarea that grows between `minRows` (default 1) and `maxRows` (default 8) lines and then scrolls, and a compact `Toolbar` action row: optional `leading` controls (an attach button or model `Select` in a `ToolbarControlGroup`), an optional quiet `hint`, and `trailing` actions (a brand Send `Button`). Never hand-build that row; the composer owns its geometry. Name it with a title-style `label` and give it an `id` so the hint describes the field; the app reads and clears the textarea in its send action. For Enter-to-send, set `submitOnEnter` and call `wireMessageComposers(root)` from `@kerfjs/ui/wire-message-composers` once; Enter or Cmd/Ctrl+Enter clicks the first trailing action, Shift+Enter inserts a newline, and an IME composition commit or an empty message never sends. Never hand-roll that keydown handler. In a chat dialog, slot it into a `DialogSurface` with `footerPresentation="floating"` and `footerInset="none"`. Never wrap a `wa-textarea` and a button in app-styled composer chrome.

For an icon with a specific meaning, set `LucideIcon.color` using `uiColor('warning-on-quiet')` or another foreground token. Use `foregroundColorVar('--app-icon-color')` for an app-owned property or `foregroundColor('#8b5cf6')` for a direct custom CSS color. Omit the prop to inherit text color. Outline stroke and solid fill both follow the chosen color; size, appearance, label, and slot remain separate props. Avoid pale fill tokens as foregrounds.
Set `LucideIcon.inline` when an icon belongs within `Text` or another sentence; the SVG flows as `inline-block` instead of its default block layout. It retains its inherited 1em size unless you set `size`.

For `Select`, mark an unavailable choice with `disabled` and optionally `disabledReason`. In a multiple Select, `selectAllLabel` and `clearLabel` opt in to localized footer actions that select enabled choices or clear the selection through normal input/change events; the app still owns the controlled `value`.

For nested action menus, use `PopupMenuItem.submenu` with item, heading, and divider entries; headings and dividers do not enter keyboard navigation. Items support `checked`, `icon`, `details`, `disabledReason`, and `tone`. The app owns choice state. For a right-click menu, use `PopupMenu` with `context: true` and `anchor` (a signal holding the pointer's `{ x, y }` client coordinates); the `contextmenu` handler sets that signal and calls `openPopupMenu(menu)`. The menu owns its zero-footprint anchor host and keeps the point across re-renders, so never wrap it in a fixed/1px/z-index anchor element or re-apply the point after a render; `openPopupMenuAt(menu, x, y)` is only for a menu rendered without `anchor`. Call `closePopupMenu` for programmatic dismissal. `openPopupMenuAt` also opens a button-triggered `PopupMenu` (one without `context`) at the pointer for one opening; it returns to its trigger once closed, so a row's visible overflow menu doubles as its context menu. For a row's trailing "…" overflow menu, pass `ListActionRow` a `trailingMenu: { label, icon, items, placement?, disabled? }` instead of the `trailingAction*` props; never compose a `PopupMenu` next to or inside a `ListItem`.

## Select lifecycle ownership

Import `@kerfjs/ui/select/register` once. It defines the form-associated
`kui-select` root and wires every Select: opening, top-layer placement,
keyboard navigation and typeahead, choosing, and dismissal. Listen for the
standard `input` / `change` events on the root and read its `value` (an array
with `multiple`). Do not add popup delays, position repairs, or animation
completion handlers in consumers.

Neutral lowered surfaces and decorative neutral fills/borders are translucent theme colors; compose nested public components directly. Default/raised canvases, foregrounds, focus indicators, and loud contrast-bearing fills remain opaque. Do not assign depth-specific component tokens in demo wrappers.

Use `ToolbarText tone="dark"` on a loud-filled toolbar surface (the inverse
`--kui-color-neutral-fill-loud`) to match dark control groups; it inverts with
the color scheme. Over a dark photo or scrim keep the default tone inside a
`BackdropImage` overlay, which takes the dark scheme under its `scrim`. It applies to read-only headings and actionable
titles at every size; default tone retains existing identity and heading colors.

Navigation transition continuity: `wireNavStack` slides the incoming view over the preserved previous view on push and the outgoing view off on pop, cross-fades both live chrome surfaces with inert snapshots, and settles/cancels an interrupted transition before starting the next. Reduced motion and duration zero settle immediately.

For a tab scene with drill-down, place a `NavStack` directly in `TabNavigatorTab.content`. Give its views structured `toolbar` and `pane` configuration and omit both stack and view `bottomToolbar`; the navigator bar remains the only bottom chrome. Wire the navigator and stack on their respective roots. See `docs/tab-navigator.md` and the catalog's **NavStack inside a tab** example. For an iOS-style translucent tab bar, set `barPresentation="overlay"`: `wireTabNavigator` measures the bar and the scenes clear it as their block-end inset; do not pad scenes for it yourself.

Use `Pane.deepInset` (also in `PaneConfig`) or `TabNavigatorTab.deepInset` for a plain scene when its scrolling content needs an extra 8px on all four sides, giving ordinary items a 16px inline gutter. The extra 8px is applied to the scroll surface, while nested Row/List/Grid item margins stay 8px. When a tab scene is a sole Pane or NavStack, configure deep inset on that child's Pane; the tab bar and top toolbar stay full width.
An edge-to-edge table or similar Pane child can read `--kui-pane-content-inset-inline-start` and `--kui-pane-content-inset-inline-end`: negate them for the child's logical margins, then add them to the child's text padding. The inherited values include routed safe areas and `deepInset`; keep the child in the Pane's single scroll slot. See `docs/app-layouts.md` for the CSS recipe.

Do not grow a collapsible search past the room beside its sibling groups: when it does not fit, the siblings wrap onto a new row while it opens. Size the expanded search to fit (`--kui-search-field-expanded-width`, or `sizing="grow"` with a fitting `growBasis`), and if a useful search still cannot fit, set aside the other controls while it is open, with `visibility="yield-to-expanded-sibling"` on those groups (they leave a 480px-or-narrower toolbar while a sibling is expanded) or behind a "…" `PopupMenu` overflow group; the app chooses which controls yield. Expanded search groups accept `expandedOverflow="visible"` to anchor app-owned suggestion/date/help surfaces below their relative root; collapsed/default groups retain existing clipping. Apps own surface placement/dismissal and use `data-search-field-keep-open` or `collapsible.keepOpenOn` for focus.

`ToolbarText` and `ToolbarControlGroup` accept typed `hideBelow`/`showBelow`
lengths (for example `px(416)`). Wire `wireToolbarVisibility(root)` from
`@kerfjs/ui/wire-toolbar-visibility` and dispose on unmount. Thresholds use the
nearest Toolbar content-box width: hideBelow hides strictly below, showBelow
shows strictly below, with complementary behavior at equality. Percentages use
that content width; em and custom properties use the item's own context. Invalid,
negative, unresolved, or contradictory values leave the item visible under this
width policy. Keep primary actions visible and offer a complementary overflow
group. See `docs/component-contract.md` "Toolbar width visibility" for lifecycle
details.

Select menus use native viewport shifting with 10px gutters: default menus grow to content (up to 20rem), while `fitMenu` matches trigger width and long labels wrap. Keep popup sizing and position repairs out of consumer CSS.

Give sibling `DialogSurface`s that render conditionally a stable `rootAttributes={{ "data-key": "…" }}` so a re-render morphs each dialog into itself (structurally identical roots otherwise match by position and swap names and open state); never wrap one in a keyed app `div`. Modal `DialogSurface` accepts a typed `preferredWidth` (`CssLength`) that overrides `size` while retaining the viewport width cap. Typed `viewportGutter` and `maxHeight` (`CssLength` or `"viewport"`) bound the modal; explicit height caps stay within the dynamic viewport minus both gutters. Omitted props keep the default caps (20px clear of each edge, 80% of the viewport height at 420px wide or narrower). Side-sheet/fullscreen geometry, application responsive choices, and preview layout remain separately owned. `height` (`CssLength` or `"viewport"`) gives the modal a definite bounded size, and `bodyLayout="fill"` hands the whole body to one child (a `SplitView` or `Pane`) that owns its scrolling. For a chat-style dialog, `bodyLayout="fill-last"` keeps leading rows (a notice) at their height and gives the last child (a `scrollable` `List` transcript) the rest, and `footerPresentation="floating"` lays the composer footer over the body, a typed `footerOffset` (default 16px) from the panel edges on a transparent background; the body reserves the measured footer height, so never add `::part(footer)` or `::part(body)` rules for it. To let the transcript scroll visibly beneath the floating composer, give the transcript `scrollClearance="block-end"` (on a `scrollable` `List` or a `Pane`): the body then publishes the footer's clearance as the inherited `--kui-scroll-clearance-block-end`, and the transcript adds it inside its own scroll area, so its last message still rests above the composer. Chrome that overlays a region's edge publishes `--kui-scroll-clearance-block-start` / `-end` the same way, and only the one scroller reaching that edge opts in (a composed Pane opts in through `PaneConfig.scrollClearance`: a Workbench `mainPane` or panel `pane`, a `CollapsiblePanel` `pane`, or a `NavStack` view's `pane`); never pad a transcript yourself to clear a footer. `headerPresentation="floating"` lays the dialog's title bar over the body's block start on the translucent `--kui-chrome-material-raised` (opaque under reduced transparency, increased contrast, forced colors, or without `backdrop-filter`); the open dialog measures it and the body reserves it. To let a transcript scroll beneath both the title bar and a floating composer, make it the body's only child (`bodyLayout="fill"`) with `scrollClearance="both"`: the body publishes the header's height as `--kui-scroll-clearance-block-start`. A `ToolbarText` as the `heading` keeps AA on the title bar by itself (normal-color title, lifted description); keep other quiet copy in the body. `presentation="bottom-sheet"` attaches the dialog to the bottom edge (iOS-style sheet): the top corners keep the dialog radius, the bottom corners are square, and the panel runs behind the home indicator and virtual keyboard while a block-end padding (the larger of `--kui-safe-area-block-end`, the `visualViewport` keyboard overlap `openDialog` measures, and `env(keyboard-inset-height)`) keeps content above them; `height` is its opening visible height and `maxHeight` its cap (the dynamic viewport minus the top safe area and one gutter). `resizable` adds a top grabber (a focusable "Resize sheet" separator; drag, arrows, Page Up/Down, Home/End) bounded by `minHeight` (default 160px) and the cap, restarting at `height` on each opening. It slides up on open and down on dismiss by default (`enterMotion` / `exitMotion` = `"standard"` keeps the dialog's scale-and-fade), with no motion under reduced motion. Never position a dialog at the bottom with your own CSS or add your own keyboard padding. For a non-modal, light-dismiss dialog use `PopoverDialogSurface` from the same subpath (native `popover="auto"`, `role="dialog"`, Kerf chrome, the same size/gutter/height/fill props, and `presentation="embedded"` for an in-flow catalog or inline preview) instead of a hand-built popover with app CSS. Name it with `label` or `labelledBy`, and describe it with `describedBy` (its `aria-describedby`), usually a title `ToolbarText`'s `descriptionId`.

Render a modal dialog as `DialogSurface` itself, a native `<dialog>`: `label` (or `labelledBy` with a `heading`, such as an xl `ToolbarText` with a description) names it, `children` is its body, `footer` holds its buttons, and `headerActions` sit before its close button (`withoutHeader` drops the header for content that owns its heading and close control). Open it with `openDialog(dialog)` and close it with `closeDialog(dialog)` from `@kerfjs/ui/surface-scaffold`; never toggle its `open` attribute. The close button, any `data-dialog-close` element inside (a Cancel button), Escape, and, with `lightDismiss`, a backdrop press dispatch a cancelable `kui-request-close` (`detail.source`: `close-button`, `escape`, or `backdrop`); cancel it to keep the dialog open (the panel pulses). The native `close` event fires once it closes. `openDialog` installs the listeners and, while the dialog is open, measures its floating header/footer, follows a bottom sheet's keyboard and grabber, and keeps that state across re-renders; import `@kerfjs/ui/surface-scaffold/register` only when a dialog may open some other way. Do not write `wa-dialog` inside a `DialogSurface`.

Toolbar visibility measurement probes and invisible state children are helper-owned and survive Kerf rerenders through `data-morph-preserve`. Actual CSS visibility stays stable while rendering removes transient parent markers, preventing geometry-driven render feedback and repeated probe recreation. Toolbar replacement, explicit internal-node removal and disposal retain their existing behavior.
