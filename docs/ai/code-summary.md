# Code summary — kerf

A directory map + reverse index ("where do I look for X?") for Claude Code sessions and other AI assistants. Keep this in sync with `src/` whenever a file is added, removed, or renamed.

## Directory tree

```
kerf/
├── src/
│   ├── index.ts                  ← public entry — re-exports everything users import
│   ├── jsx-runtime.ts            ← JSX → SafeHtml string emitter
│   ├── jsx-types.ts              ← typed IntrinsicElements (KF-75) — per-tag attribute contracts, catches JSX typos at compile time. Header documents the provenance (WHATWG HTML Living Standard + SVG 2, not another framework's property-surface table), the rule that `boolean` means *HTML boolean attribute* (KF-436 — enumerated attributes take `"true"`/`"false"` strings), and every deliberate deviation from the spec
│   ├── reactive.ts               ← signal/computed/effect/batch (re-export) — `signal()` routes through the `devHooks.signalFactory` slot (KF-176's DevSignal) and `effect()` through `devHooks.wrapEffect` (KF-238's enter/exit wrap so `delegate()` can detect inside-effect callsites). Both slots are empty unless the consumer imported `kerfjs/dev`. NOTE: `signalFactory` is resolved at signal CREATION, so signals created before the dev entry installs stay plain.
│   ├── dev-signal.ts             ← KF-176 — `DevSignal<T> extends Signal<T>` subclass that warns once on writes to signals with no subscribers (Rule 7 helper). Opt-in via `KERF_DEV_WARN_UNTRACKED_SIGNALS=1`. KF-431: the constructor is chosen at signal CREATION, so this is the one warning whose coverage depends on install order — opting in also prints a one-shot coverage-boundary notice, because `Signal.prototype.value` is non-configurable and existing signals cannot be retro-fitted without a per-signal registry production would pay for.
│   ├── dev-hooks.ts              ← the dev-hook registry — the ONLY seam between core and the diagnostics. Core reads nullable slots (`devHooks.listRebind?.(...)`) instead of importing a `dev-*` module, so with nothing installed every slot is `undefined` and the whole family is unreachable from the main entry (that is what lets a bundler drop it). Replaces the old inferred `isDevMode()` gate, which read `globalThis.process?.env?.NODE_ENV` and therefore reported DEVELOPMENT inside production browser bundles; that helper (`utils/devMode.ts`) and its test are GONE as of KF-430 — a warner's only gate is now its own `KERF_DEV_WARN_*` variable. Slots ending in `Enabled` are predicates for the call sites that must decide whether to do expensive preparatory work first. Fourth sanctioned module-level mutable location (Design rule 5); like `store.ts:REGISTRY` it requires exactly one copy at runtime, which `splitting: true` guarantees.
│   ├── dev-warn-config.ts        ← KF-434 — the SWITCH layer for the opt-in diagnostics (the second gate; installation is the first). `enableWarnings({...})` writes an in-memory override map, `devFlag(envName)` reads it and falls through to `globalThis.process?.env`; explicit calls win both ways. Exists because a browser realm has no `process` at all and no bundler `define` can reach the read (it goes through `globalThis.process` into a local), so the env vars left the whole family unreachable in the environment that wants it most. Dev chunk only. Internal apart from the `enableWarnings` re-export on `kerfjs/dev`
│   ├── dev.ts                    ← the `kerfjs/dev` entry — imports every `dev-*` module and installs `DEV_HOOKS` into the registry. The consumer gates it with THEIR flag (`if (import.meta.env.DEV) await import('kerfjs/dev')`), which folds to false in their production build so the chunk is never emitted or fetched. Installation decides whether the diagnostics are PRESENT; `enableWarnings({...})` (re-exported here, KF-434) or a `KERF_DEV_WARN_*` env var decides which are ON — the former is the only one that works in a browser.
│   ├── dev-row-key-warn.ts       ← KF-173 — always-on-when-installed warn when an each() row has no `id`/`data-key` (positional matching silently shifts row state). Moved out of `utils/rowContract.ts` so it ships in the dev chunk instead of the main bundle; still borrows `truncateRowHtml` from there.
│   ├── dev-invariants.ts         ← KF-400 — opt-in structural audit of every list binding against the live DOM after each render (`KERF_DEV_INVARIANTS=1` warns, `=throw` throws; unset is a total no-op, no DOM walk). Checks marker liveness, marker-id agreement, row parentage/liveness/order, row aliasing across bindings, region overlap between lists sharing a parent, and (KF-416) row-count-vs-source-length — the last is the only EXTERNAL check (all others confirm the binding agrees with the live DOM; a wrongly-emptied but self-consistent binding passes them), and is what would have caught KF-411 at its causing render. `mount()` supplies per-list expected counts only when the checks are enabled (`listInvariantsEnabled()`), so production pays nothing. Reports a kerf bug, not an app pattern, which is why it is the one member of the family whose message says "please report it". Paired with the reconciler fuzz harness: the harness generates sequences, these checks notice one went wrong.
│   ├── dev-parser-repair-warn.ts ← KF-405 — opt-in warn (`KERF_DEV_WARN_PARSER_REPAIR=1`, one-shot per tag pair) when the rendered markup puts a block-level element inside a `<p>`. The parser closes `<p>` before block content, so the `<p>` ends up EMPTY and its children become siblings. Measured impact is narrower than it looks: kerf reconciles the repaired tree correctly and updates/inserts/toggles all keep working — what's lost is the authored structure and anything (CSS, querySelector) depending on it. Worth a warning because the symptom is three levels from the cause. `findParagraphRepair()` is a single open/close walk over kerf's own well-formed output, exported for direct testing.
│   ├── dev-listener-warn.ts      ← KF-174 — opt-in dev `MutationObserver` + `addEventListener` prototype patch that warns when a node carrying an imperative listener is removed/rebuilt by the morph (Rule 4 helper). Opt-in via `KERF_DEV_WARN_REBUILT_LISTENERS=1` in dev; production unchanged.
│   ├── dev-store-warn.ts         ← KF-212 — opt-in dev warn when `defineStore.set(next)` has any key from the current state missing in `next` (Rule 8 partial-set helper). Per-store one-shot dedup; opt-in via `KERF_DEV_WARN_NARROW_SET=1` in dev; production unchanged.
│   ├── array-signal.ts           ← arraySignal (KF-92) — granular collection signal; lives at the kerfjs/array-signal subpath (KF-95) so non-users shed ~1 KB. `update()` bumps the item's content version (item-version.ts) so a same-ref mutation is visible to the row memo (KF-418).
│   ├── item-version.ts           ← KF-418 — a shared `WeakMap<item, number>` content version so a same-ref `arraySignal.update()` (which keeps the identity the row memo is keyed on) re-renders the row in EVERY consumer: other lists, other mounts, plain-array filter() views. `bumpItemVersion` (called by array-signal.update), `itemVersion` (read by each() — CacheEntry stores the version, a hit requires it to match). Lives in the MAIN bundle (not on ArraySignal) so each() reads it without importing the subpath (KF-95); an `anyVersioned` flag keeps apps that never mutate in place at zero per-row cost.
│   ├── store.ts                  ← defineStore + resetAllStores + REGISTRY. Dev-only: `get()` returns a deep read-only Proxy (via `utils/devReadonly.ts`, reached through the `devHooks.readonlySnapshot` slot); `set()` unwraps any get()-derived proxies with `toRaw` so the signal stores plain objects. Prod returns the bare reference.
│   ├── mount.ts                  ← mount() — segment-aware render bound to effect(); adopts an inert-document rootEl (defaultView === null) into the live document before first render (KF-243 defense-in-depth for the KF-240 WebKit inert-doc parse bug)
│   ├── morph.ts                  ← native general-purpose DOM reconciler (replaces morphdom); exported publicly as morph() (KF-150). Binding-marker aware: its child pairing steps past the wiring-inserted text node a `kfb:`/`kfbr:` marker owns (via bindings.ts `boundTextNodeOf`), so a bound hole mixed with static text siblings survives a morph (KF-374 — the static sibling used to be dropped). Two positional-lookahead recovery steps when a sibling shifts the cursor: 2.5 elements (KF-377 — a later same-tag unkeyed element is MOVED up, not cloned, so list containers/stateful elements survive a preceding removal), and 2.6 `kf-list:` markers (KF-382 — the marker is matched on exact data and moved WITH its row region, with captureFocus/restoreFocus around the move, so an each() binding never detaches and rows keep identity + caret). KF-385: the row region is `afterListRegion()` = marker through LAST owned row (interlopers between rows included, scan bounded by the next list's marker), used BOTH for the 2.6 run and for the cursor advance after a positional marker match — the old contiguous-owned-run reading let a single injected node shrink the region to the bare marker (run) or park the cursor inside the list (advance), either of which wedged a trailing template sibling in among the rows
│   ├── segment.ts                ← Segment types (static/list/mixed) + flatten helpers
│   ├── each.ts                   ← each() — keyed list iteration with per-item memo. KF-392: third arg is `cacheKey` OR an `EachOptions<T>` object `{ cacheKey?, key? }` (overloaded; the bare form still works). A `key` becomes the list id (namespaced `k:`) and does NOT consume the call-order counter, so keying a conditional list also stabilizes unkeyed siblings; duplicate keys in one render throw. `RenderContext.keysThisRender` (cleared by mount each render) enforces uniqueness. KF-388: a list's id is its call-order index, so `RenderContext.bindingSources` records which data source (arraySignal instance) each id last held; `eachGranular` compares identity FIRST and forces the snapshot route on a mismatch, so a queued patch can never be applied to another list's binding. The check lives here, not in the reconciler, because only each() can still emit the full item snapshot the rebuild needs (granular segments carry `items: []`).
│   ├── html.ts                   ← KF-333 — `html` tagged template at the kerfjs/html subpath (no-build authoring path for CDN/importmap consumers). Thin front-end over the exact JSX machinery: text holes via jsx-runtime's `_toSegment` (escaping, SafeHtml/each() list-segment passthrough, signal → bindText), attr holes via `_assertEmittableAttrName` + `bindAttr` (signals, grouped into one marker attr per element at the tag-close `>`) or `_renderAttrVerbatim` (statics — NO camelCase aliasing; authors write real HTML names). Parse-once-per-callsite via a WeakMap keyed on the template strings array; `_parseCount()` test hook. mount/morph/reconcilers unchanged.
│   ├── bindings.ts               ← KF-294 — fine-grained signal bindings. A `Signal` handed straight into a JSX attr (`class={sig}`) or text hole (`{sig}`) inside a mount() emits a marker instead of stringifying; a wiring pass attaches one effect per hole after parse so the node updates without a render re-run. TWO scopes with disjoint marker namespaces: GLOBAL holes (`data-kfb` / `<!--kfb:id-->`) wired by wireBindings() over the mount root; ROW holes inside each() (`data-kfbrow` / `<!--kfbr:id-->`, row-local ids) captured by captureRowBindings(), wired/disposed by BOTH reconcile paths at each row node's create/remove (snapshot: buildFreshNodes/removeOldNodes; granular: applyInsert/remove/update) — so select-row updates fire only the ~2 changed effects (no render, no reconcile). SSR/toString snapshots the value. Optimized wiring: root-attr holes resolved allocation-free (no querySelectorAll/Map for the common `<tr class={sig}>` row). KF-347: `carryOrRewireRowBindings` — the carry-vs-rewire decision for rows whose node survives an in-place update (granular reuseBound + inplace updateRowInPlace, incl. the html-identical no-op arms): same signal instances per hole → carry for free; any changed instance → dispose + re-wire against the surviving node, so self-reading holes update after arraySignal.update(); text-hole wiring reuses the marker's inserted text node (WeakMap) so a rewire never stacks a duplicate. RESERVED NAMESPACE (KF-314): the wiring pass matches markers by id across the subtree with no ownership check, so `data-kfb`/`data-kfbrow` + comments beginning `kfb:`/`kfbr:`/`kf-list:` are a reserved consumer contract — a consumer that emits one can collide with a real binding's id and steal its effect; documented in docs/2-reactivity.md and pinned by a marker-constant test. SECURITY (KF-322 completes KF-306): the bound path's attr NAME is trusted at write time — `on*` and malformed attribute names are rejected at binding registration in jsx-runtime's `jsx()` signal branch via the shared `assertEmittableAttrName` (the same helper renderAttr uses for static attrs), so a signal bound to `onclick` can never reach `setBoundAttr`→`setAttribute('onclick', …)` and install a live inline handler.
│   ├── list-render-state.ts      ← KF-336 reified dispatch state machine — ListRenderState (unbound/empty/bound), deriveListRenderState(count), decideListPath() with the documented transition table (first-render/empty-binding/no-patches/replace/count-drift → snapshot; else granular; cachekey-drift + render-threw layered on in each.ts). Pure + directly unit-tested, incl. the previously-c8-ignored count-drift arm
│   ├── list-reconcile.ts         ← top-level dispatcher (KF-112) — re-exports BoundItem / ListBinding / endAnchor and defines reconcileList; its non-empty-binding granular precondition is the DOM-side restatement of list-render-state's `bound` state
│   ├── list-binding.ts           ← BoundItem / ListBinding shape + endAnchor() (KF-116) — extracted to break the circular import between list-reconcile.ts and its sibling reconcilers
│   ├── list-reconcile-snapshot.ts ← snapshot reconcile path (classify / bulk-parse / LIS / move)
│   ├── utils/rowContract.ts       ← KF-103 "exactly one top-level element per row" helpers + KF-389/KF-417/KF-420 namespace-aware row parsing: `parseRowTemplate(html, parent?)` returns a DocumentFragment parsed in the list parent's namespace. `foreignWrapper(parent)` picks the wrapper — `<svg>` for an SVG parent or `<math>` for a MathML parent — EXCEPT when the parent is an HTML integration point, where rows are ordinary HTML and take the unwrapped path: SVG `foreignObject`/`desc`/`title` and MathML text points `mi`/`mo`/`mn`/`ms`/`mtext` (KF-420; `annotation-xml` is a conditional integration point and out of scope). Every reconcile path that creates a row node threads its `liveParent` through — including the bulk offender-finders and `rowContractError`, so a contract violation's reported count matches the namespace the reconciler parsed in (KF-420).
│   ├── list-reconcile-inplace.ts ← snapshot fast path: when refs are unchanged in order, morph changed rows in place (reusing the granular surgical/morph ladder) instead of node-replacing them — avoids table relayout for external-state-driven row changes
│   ├── list-reconcile-granular.ts ← granular reconcile path (KF-92 patch-driven, KF-93/94 bulk parse)
│   ├── list-reconcile-fast-paths.ts ← KF-198 attribute-only + KF-206 text-content-only fast paths for the granular update path. KF-390: the attribute-only path is the THIRD attribute writer (with morph.ts and bindings.ts) and now calls `syncFormProp` at both its set and remove sites, so a controlled checked/value on a row's top-level element can't go stale just because the diff took the fast route.
│   ├── list-reconcile-focus.ts   ← focus snapshot/restore around the move pass (engine-quirk fix); also reused by morph.ts's 2.6 marker-run move (KF-382), since that move can carry a focused row too
│   ├── attrSelector.ts           ← attr / AttrSpec<N,V> — two overloads: static attr(name,value)→AttrSpec (with .attrs spreadable JSX object), dynamic attr(name)→factory; cssEscapeIdent + escapeCSSString internals
│   ├── delegate.ts               ← delegate<T> + delegateCapture<T> (generic element type for handler arg) + DelegateOptions; BOTH helpers default to closest()-style walk-up matching and pass the matched ancestor — delegateCapture unified onto closest() (BREAKING; opt into old direct-match via { match: 'direct' }); shared makeListener() applies match mode + rootEl.contains() guard; calls warnIfInsideEffect() at the top of both helpers when KF-238's gate is on
│   ├── renderDocument.ts         ← renderDocument(node, {doctype?}) — SSR helper prepending `<!DOCTYPE html>` to a SafeHtml/string (the `"<!DOCTYPE html>" + page.toString()` boilerplate every server app repeats). Barrel export; pure string work, no DOM.
│   ├── actions.ts                ← action() + delegateActions() at the kerfjs/actions subpath — the blessed data-action table idiom. action(v) = attr('data-action', v); delegateActions(root, event, table, opts?) wraps ONE delegate() on `[data-action]` and dispatches by the matched element's attribute value (custom attr via opts.attr; match inherited). Thin layer over attr + delegate; returns a disposer; no per-instance state.
│   ├── attach.ts               ← attach() at the kerfjs/attach subpath — bind a non-kerf widget's lifecycle to ONE existing DOM node (a data-morph-skip host). NOT React useEffect (no dep array, no re-run, no render-phase/hook-order scoping — node already exists, setup runs once now); closer to connectedCallback/disconnectedCallback, Svelte onMount(()=>()=>cleanup), Solid onCleanup. attach(node, setup): runs setup(node) now (may return a teardown); teardown runs ONCE when node leaves the document (a MutationObserver on node.getRootNode() subtree re-checks node.isConnected on each mutation — catches direct + ancestor removal, morph swaps, remountOn replacement) OR the returned (idempotent) disposer is called. Re-creation NOT handled — a fresh node is a fresh call; pair with kerfjs/remount. Overlaps kerfjs/scope's observeRemovals (also MutationObserver auto-dispose, but subtree-scoped). DOM only (no signals, no render core) — smallest subpath (~0.19 KB). Closure-local state only.
│   ├── remount.ts               ← remountOn() at the kerfjs/remount subpath — the OPPOSITE of morph-by-default: force wholesale subtree REPLACEMENT on key change. remountOn(parent, key, render, options?): watches key (a ReadonlySignal OR a thunk () => K) in an effect; on Object.is change, tearDown() (run onMount cleanup, dispose old mount, parent.replaceChildren()) then mount(parent, render) fresh, then options.onMount(parent). Unchanged key (incl. a thunk whose inputs moved but value stayed equal) → left alone, so per-row reactivity in render updates in place. RemountOptions.onMount(root) runs after each (re)mount with the live subtree (bind imperative widgets here — render returns a string, no live node yet); its returned cleanup runs BEFORE the next remount + on dispose (return attach()'s disposer for synchronous teardown). Owns parent's children; returns a disposer. Names the hand-rolled data-key=`gen-${n}` + data-morph-skip trick. The outer effect tracks ONLY the key (mount's inner effect is independent, so render's reads attach there). Pairs with kerfjs/attach. Closure-local state only. Imports mount+effect (pulls core, ~10.2 KB).
│   ├── timing.ts                ← debounce() + throttle() + debouncedSignal() at the kerfjs/timing subpath — the hand-rolled `let timer; clearTimeout; setTimeout` pattern, blessed. debounce(fn,ms): trailing-edge, runs ms after calls stop with the latest args, timer resets per call. throttle(fn,ms): leading invoke + at most one trailing per ms (burst collapses to one trailing call), holds the rate for a beat after trailing. Both return a callable + cancel()/flush(). debouncedSignal(source,ms): a ReadonlySignal<T> trailing source by ms (internal effect + debounce writing to an out signal) — live subscription for app-lifetime signals; drive your own effect with debounce() for a disposable variant. Closure-local state only. debounce/throttle dependency-free; debouncedSignal imports signals (no render core) — tiny (~1.8 KB with the signals chunk).
│   ├── list.ts                  ← bindList() at the kerfjs/list subpath — a DISTINCT keyed list from each(). render(item) has two modes (probed per row via asElementRow): CONTENT mode (returns MountResult) → kerf creates the tag el + mount()s content inside (per-row reactive); ELEMENT mode (returns HTMLElement or { el, update?, dispose? }) → that element IS the row (app owns tag/class/data-attrs/listeners). KF-492 fix: element rows are KEYED/REUSED — reconcileItem() keeps the same element when the key persists but the item object changes (append/remove/reorder/fresh-objects), refreshing content via the optional update(item); caller's dispose runs ONLY on genuine removal (not on surviving rows). Content rows still rebuild on identity change (their mount re-renders). The granular update patch reuses element rows + re-keys the rows map if the key changed. A list may mix modes. Content-mode render runs once extra at creation for the probe (render must be a pure projection). RowElement type widens render's return. KF-496: options.before (a Node or () => Node|null) makes rows a contiguous block ending BEFORE that node via endAnchor() (used in both syncRows' reverse-pass ref and the granular insert/move/rebuild positions) so parent can hold fixed trailing siblings; ignored when virtualized (rows own the sizer). Each content row is individually mount()ed (per-row fine-grained reactivity — a signal one row reads updates just that row, no full-list pass) + optional viewport virtualization ({rowHeight, overscan}: only windowed rows render, sizer padding-top/bottom keeps scrollHeight honest, scroll rAF-throttled). KF-501: rowHeight is a fixed `number` (O(1) window) OR a `(item,index)=>number` for app-declared VARIABLE heights — a prefix-sum `offsets[]` (rebuilt only when items change, via a heightsDirty flag set in the effect; not per scroll frame) + binary-search findStart/findEnd for the window; sizeVisibleRows sets each visible row's style.height from offsets. KF-502: rowHeight also `{ estimate }` for MEASURED heights — variableHeightAt returns measured.get(key) ?? estimateAt; the app reports real heights via the returned handle's setHeight(key,px) (keyed by list key via indexByKey, survives reorders) stored in a `measured` Map; when a remeasured row is fully above the viewport (offsets[idx+1] <= scrollTop) pendingAnchorDelta accumulates and scheduleRender applies it to parent.scrollTop before the next render (anchor correction, no content jump); setHeight is a no-op for fixed/declared/unknown-key. KF-512: rebuildOffsets prunes `measured` to the live key set each pass (a key gone from the source drops its height; a key only scrolled out of the window stays) so a churning measured list doesn't leak — a returned key re-measures via the estimate. bindList now returns a BindListHandle ((()=>void) & { setHeight }). observeRowHeights(handle) (also kerfjs/list) installs ONE ResizeObserver over the visible rows (via a GC-tied WeakMap VIRTUAL_INTERNALS exposing visibleRows()/onRender()) forwarding offsetHeight → setHeight, re-observing on each window render; no-op if non-virtualized or no ResizeObserver. KF-503 adoption ergonomics: virtualize.minRows renders ALL rows (no windowing, zero padding, same inner-container structure) while total < minRows and windows at/above — one DOM shape, caller never branches; virtualize.containerClass/containerId set on the inner sizer + handle.container exposes it (undefined when non-virtualized); bindList now ALSO installs a ResizeObserver on parent (scheduleRender on resize) so a 0-height-at-mount list self-heals once laid out and a resized container re-windows (scroll-only fallback where RO absent). Core references ResizeObserver only for this parent-resize path (optional-chained). Reads source.value so a signal<T[]> OR arraySignal works. KF-478: a non-virtualized arraySignal source takes a GRANULAR patch path (applyPatches over an ordered `order[]`, O(patches)) — drains _consumePatches() every render to keep the queue clean; a `replace`, a shared signal (empty drain), a plain signal, virtualization, or first render fall back to the keyed reverse-pass diff (syncRows). Rebuilds a row on item-object identity change (both paths); owns parent's children. Closure-local state only. Imports mount+effect (pulls core).
│   ├── async.ts                 ← resource() at the kerfjs/async subpath — async-state container with a built-in stale-response guard. resource<T, I=void>(options?) → { value (tracking read of {status,data,error,progress,input,revision}), run(fetcher), run(input,fetcher), reset() }. .run() owns idle→running→completed|failed transitions + a per-resource generation counter so only the LATEST run resolves; never rejects (error lands in value.error); keeps prev data (stale-while-revalidate); opt-in progress via a report(completed,total) callback the fetcher receives. The run(input,fetcher) overload threads input to value.input for running/completed/failed (latest-wins) so the error branch can recover which request failed. ResourceOptions.cacheKey(input) keeps a per-key Map cache (revisiting a loaded key paints its cached slice instantly while it revalidates; never-loaded key clears data; reset clears the cache). value.revision bumps only when data changes by options.equals (default Object.is) — the skip-redundant-paint hook. KF-493: cached(key)/cachedKeys()/clearCache(key?) expose + evict the cache read-only (no run needed; clearCache doesn't touch value). Signals only (no render core) — tiny (~1.9 KB).
│   ├── scope.ts                 ← disposeScope() + disposeSubtree() + observeRemovals() at the kerfjs/scope subpath — tie disposers to an element's lifetime. disposeScope(el)→Scope (WeakMap-keyed, accumulating; add/mount/effect/delegate register a disposer; dispose() best-effort + idempotent + fresh-after). disposeSubtree(root) sweeps root + descendants (walks querySelectorAll('*') vs the WeakMap — no marker attrs). observeRemovals(root)→disconnect: MutationObserver auto-disposes on removal. GC-tied `const` WeakMap (Design rule 5 exempt). The convenience wrappers pull in core via mount/effect/delegate.
│   ├── overlay-position.ts       ← KF-511 — the anchored-positioning primitives extracted from overlay.ts (they stand alone: any element, no overlay lifecycle). PopoverPlacement, AnchorPositionOptions, positionAnchored(el, anchor, opts) (position:fixed set FIRST then measured — KF-507 — below/above flip-on-overflow, horizontal clamp, align start/end, gap), autoReposition(el, anchor, opts) (positions once + re-runs on scroll(capture)/resize, returns a disposer). Re-exported from overlay.ts so kerfjs/overlay is unchanged; popover()/tooltip() build on autoReposition. No signals/render core.
```

## Build outputs

`npm run build` → `tsup` → `dist/`. TypeScript is dual-track (KF-375): the native **TypeScript 7** compiler — installed as the `typescript7` npm alias, invoked as `node node_modules/typescript7/bin/tsc` — runs every typecheck gate (`npm run typecheck` and the three `-p` dist-typing gates plus the docs-examples compile), while `typescript@6` (the JS-API bridge; native 7 ships no JS API) remains the resolvable `typescript` package for tsup's `.d.ts` emit and typescript-eslint (whose peer range caps at `<6.1.0`). `tsup.config.ts` sets `dts.compilerOptions.ignoreDeprecations: '6.0'` because tsup hardcodes the TS-7-removed `baseUrl` into its dts build — the waiver lives there, not in tsconfig.json.

Outputs:

- `dist/index.js` (ESM bundle, ~12 KB min+gz including `@preact/signals-core`; ~13 KB if a consumer also imports `arraySignal` from `kerfjs/array-signal`. See `bench/results.md` for the per-shape numbers.)
- `dist/index.d.ts` (types)
- `dist/jsx-runtime.js`
- `dist/jsx-runtime.d.ts`
- `dist/array-signal.js` (`kerfjs/array-signal` subpath, KF-95)
- `dist/array-signal.d.ts`
- `dist/html.js` (`kerfjs/html` subpath, KF-333 — the `html` tagged template)
- `dist/html.d.ts`
- `dist/testing.js` (`kerfjs/testing` subpath)
- `dist/testing.d.ts`
- `dist/chunk-*.js` — shared chunks emitted by tsup's code splitting. Both entries import their shared modules (`SafeHtml`, the store registry, etc.) from these chunks so each module-level value exists exactly once at runtime. Do not import directly; consumers always go through the named entry points.
- Source maps for everything

`tsup.config.ts` runs with `splitting: true` (KF-14 / KF-15) — without it, esbuild bundles each entry independently, which both duplicates shared classes (breaking `instanceof` checks across entries) and tree-shakes shared module-level state into broken stubs.

The five entries (`index`, `jsx-runtime`, `testing`, `array-signal`, `html`) each emit a tiny shim that re-exports from one of the shared chunks; the bulk of the runtime lives in those chunks. That keeps the cross-bundle brand symbols (`Symbol.for('kerfjs.SafeHtml')`, `Symbol.for('kerfjs.ArraySignal')`) addressing exactly one class identity per kerf copy.

Runtime dep (`@preact/signals-core`) is external — consumers' bundlers pick it up from their own `node_modules`.
